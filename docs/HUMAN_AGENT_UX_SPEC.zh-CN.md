# CopilotMail 人类与 Agent 交互规范

本文把 `DESIGN.md` 的视觉原则落实为可开发、可验收的行为规格。它不改变
领域安全模型；界面只能呈现后端真实授权和状态。

## 1. 人类邮件工作流

### 1.1 收件箱

- 登录后直接进入默认可读的人类邮箱；当前邮箱的身份、地址和可发送性持续可见。
- 列表行显示真实的发件人、主题、预览、接收时间、未读、星标和附件信息。
- 搜索是局部、可清除且可由 `/` 聚焦。真实空收件箱使用生产交付文件
  `inbox-zero-v1.webp`（PNG 仅为审计源文件）；搜索无结果是另一个业务状态，在专用
  素材生成、目检和登记前只使用明确文案与“清除搜索”动作，不得复用空收件箱插画。
- 首批快捷键只绑定已经存在的收件箱、搜索、打开、返回、星标和刷新操作。

### 1.2 阅读与回复

- 详情顶部仅提供返回、星标和可回复时的回复。归档、删除、转发、下载等功能在
  没有 API 前不得出现。
- 纯文本正文、附件元数据、截断提示和回复权限保持当前安全语义。
- 如果请求失败，明确显示原因、重试动作和当前选择的邮件；不能用空白面板替代错误。

### 1.3 写信、草稿与已发送

- 写信界面固定显示服务端派生的 From 身份和只读/可发送状态。
- 自动保存、CAS 冲突、未知提交冻结和投递对账是可见但不喧宾夺主的状态。
- 草稿用宽列表表达可恢复状态，不保留虚假的详情列。
- 已发送只呈现当前契约允许的提交和投递聚合；不伪造正文或收件人详情。

## 2. Agent 作为第一公民

Agent 不通过网页“点击”完成邮件处理；其一等公民体验是稳定、低歧义、可审计的
API/SDK/Event 交互。人类界面只在后端存在受控投影时，为 Agent 的身份、Owner、
当前 Token 权限交集与邮件控制面提供可理解的观察与操作面；它不得把这些记录表述为
运行时在线状态或执行监控。

### 2.1 现阶段可实现表达

- 邮箱选择器分组并标识 `Human`、`Agent`、`Shared`、`Group`。
- 邮箱实体复用共享 `IdentityBadge`：原创 SVG、身份形状和当前语言下的可见文字共同
  表达身份；不使用隐藏英文后备文本，也不从地址补造 Owner、Scope 或委托事实。
- Agent 邮箱必须显示 Agent 标识和当前邮箱地址；不能根据地址猜测 Owner 或权限。
- 不可发送、会话冻结和权限拒绝使用 API 事实驱动的 `StatusIndicator`，以图形、形状和
  明确文字共同表达；不得推断运行、投递、权限或审批状态。

### 2.2 已接入的受控观察面

`GET /api/v2/agents/{agent_id}/inspector` 已为 Human-only 的 `identity.manage` 管理端
提供单 Agent 快照。管理端的“Agent 检视”要求管理员**显式输入**一个规范 UUID，首次
进入不预取、不轮询、不建立 Agent 目录；成功读取后只在当前 React 内存视图中显示以下
事实：

- Agent/Owner 的同租户身份与生命周期状态；
- Agent Profile 的环境、风险、用途、复核截止及“已到期/待复核”状态；
- 有效凭据数、下一次到期、最近认证时间，以及有效凭据 scope 与当前 RBAC 的交集；
- 生产邮件策略准入、订阅状态计数与最近控制面处理操作时间。

成功结果的第一层必须是共享 Context Bar：标题只使用 Agent 名称和服务端生命周期，事实只
使用 Agent ID、Human Owner、环境和 `observed_at`，唯一操作是显式刷新。下方只呈现边界与
复核、Token 交集和邮件控制面这些尚未在 Context Bar 重复的事实组。刷新失败而保留旧快照时，
界面要明确该记录是“上一次已确认的观测”，不是实时状态。

浏览器将成功 JSON 视为不可信输入，必须按上述最小 DTO 精确校验键集合、UUID、可枚举值、
RFC 3339 时间、`u32` 计数、允许的 scope 和跨字段派生关系；任意额外的运行态/凭据字段或
矛盾的复核、Token、邮件准入状态均在渲染前失败关闭。

UUID 的本地校验会以 `aria-invalid` 和与输入框绑定的本地说明呈现；畸形或保留 UUID
不会发起请求。`403` 与统一的 `404` 不提供重试，只有 API 明确标记为可重试的故障才显示
重试动作。身份、生命周期和受控状态均以原创的图形轮廓加文字说明表达，不能只依赖颜色；
复核 `scheduled` 在界面中只能表示“未到期”，不表示人工已安排、已批准或运行任务。

刷新会保留已确认的快照和刷新控件，使键盘焦点不会因面板卸载而中断；成功完成后用简短的
`aria-live` 状态通知“已读取”或“已刷新”。若刷新失败，旧快照仍只是上一次已确认记录，
错误说明不会把它误写成新的实时状态。

该接口不提供邮箱、委托、凭据材料、邮件内容、心跳、部署、队列、任务或 execution
信息。界面必须将“最近控制面处理操作”表述为控制面记录，不能把它写成在线、心跳、
投递或执行状态。`404` 只显示统一的“目标不可显示”文案，`403` 不暗示目标存在；
错误只可显示本地化说明与安全的 Request ID，不能回显服务端细节。快照或错误不得进入
URL、浏览器历史、`localStorage`、Toast 或静态卡片。

管理端角色和审计视图展示持久化的 `service` Actor 时，使用独立的 `service` 身份种类；
它可复用受边界系统核心图形作为视觉语法，但文本必须保持为 `Service`/`服务`。这不会
把事实主体改称为 System，也不会增加 Service wire 身份或授权含义。

### 2.2.1 精确 Agent 发件证据（P3）

`POST /api/v2/agents/{agent_id}/mail-submissions/{submission_id}/evidence` 是单个已确认
Agent 的**精确读取**，不是发件目录、运行大屏或 Agent 操作入口。管理端只可在当前
Agent Inspector 快照已成功取得后的内存视图中提供该入口；管理员还必须主动输入一个
规范的 submission UUID。没有第二个 UUID 时只显示带标签和说明的输入，不显示示例
发件、空白证据卡或虚构的投递状态；不预取、轮询、枚举、缓存或把这对 ID 写入 URL、
历史、`localStorage` 或 Toast。HTTP 使用 `POST` 并不把它变成邮件写入：它仍只读取
一对已存在的不可变证据；但每次成功观测会追加 High 风险读取审计和 Outbox，因此不得
自动重放。Admin Cookie 的此请求必须经过既有 Origin/CSRF 状态变更保护。

该读取只允许 Active Human，且同时具备 `identity.manage` 和 `audit.read`；受限 bearer
还必须同时含有这两个 scope。服务端以认证租户、Agent UUID 和 submission UUID 做精确
绑定，并在事务内复核 Active Human 后才披露。成功结果只能呈现：

- 提交 UUID、提交状态及创建/更新时间；
- 不可变准入 ID/时间、策略激活/版本及其批准请求 ID、最小收件计数，以及可选的首次
  联系人批准请求 ID；
- 可选的最新不可变投递**聚合**：观测时间、终态标记和收件人/已投递/失败/排队/未知计数；
- `mail.submission.requested`、`agent.mail.admitted` 与终态时对应终态动作的最小审计引用
  （事件 ID、动作、时间）。

上述时间全部来自 PostgreSQL，而非浏览器时钟：请求审计精确绑定
`submission.created_at`，准入审计精确绑定 `admitted_at`，终态审计绑定对应终态动作；
策略激活和批准则在当时的持久化时间上验证。批准请求、完成或决定若晚于策略激活/准入，
不能倒灌为历史批准。初始 pending intent 的 `updated_at` 也不能用来否定较晚写入的
`admitted_at`；`accepted_at` 不显示给 Human，仅在服务端证明可选投递聚合确实发生在接受
之后。页面必须按这些已返回或已引用的时间展示事实，不能用排序、色彩或文案补造因果。

`delivery=null` 只能写为“本次读取没有返回投递快照”，绝不能改写成未投递、失败或
Agent 未运行。审计引用必须置于默认收起的 `EvidenceInspector`，展开后仍只显示这些
最小引用；不把详情、收件人、邮件地址、SMTP/提供方、正文或投递协议记录补进界面。

缺失、跨租户、非 Agent、Agent/submission 不匹配或没有 production 准入的目标统一为
`404`，不向操作者揭示哪项条件失败；`403` 同样不暗示目标存在。成功读取会同事务写入
`agent.mail_submission_evidence.queried` 审计及其 Outbox 事件，拒绝、失败和 `404` 不写
“读取成功”证据。该事件只证明 Human 查阅了受控证据，绝不证明邮件已投递、Agent 在线、
执行完成或存在委托关系。响应只会在这次 `POST` 的审计/Outbox 提交成功后返回；它们以同一
服务端 `observed_at` 绑定精确目标、返回状态、准入/策略标识和“是否有投递快照”等最小事实，
不复制邮件或批准内容。

这个视图没有运行状态、心跳、部署、执行/委托、邮箱、收件人、SMTP/提供方或正文信息。
浏览器继续把响应当作不可信输入，严格拒绝未知字段和跨字段矛盾；无契约字段不得用色彩、
图标、占位模块或推测性文案补齐。

### 2.3 邮件域名治理的双主体边界

自定义邮件域名是 Human 与 Agent 共同可治理的控制平面资源，不是浏览器专属配置。Human
管理员使用管理端的列表—详情工作台；Agent 使用同一版本化 API/SDK。两类入口都必须由服务端
实时验证同租户、`mail.admin`、生命周期和 CAS 版本，前端显示的状态不能成为授权或写入依据。

Human 工作台把实际步骤压缩为可核对的顺序：注册成功后只在当前 Dialog 展示一次 ownership token；
关闭、导航或认证上下文重建即清除，绝不写入 URL、历史、`localStorage`、Toast 或静态页面。写入
DNS 后，操作者提交 token 与 DKIM selector 取得 DNS 证据；只有最新 challenge 的合格证据使资源
进入 `verified`，管理员再显式确认 Activate 才能进入 `active`。DNS 已验证、控制平面 Active 和
数据平面 projection Ready 必须分别呈现，不能以绿色标识或一句“已就绪”混合表达。

路由设置与生命周期分离，`route_version` 是每次更新所需的 CAS 证据。冲突后只能重新读取详情、
由操作者或 Agent 根据最新版本提交新的意图，不能在客户端自动覆盖。邮件引擎投影由 Outbox Worker
异步完成，`not_projected`、`pending`、`ready`、`failed` 及引擎实际启停/最近尝试事实是独立的
观察面；`active` 不承诺已经能够收发邮件。

若写响应因网络中断、`5xx` 或无效 `2xx` 而无法证明，工作台冻结该域名全部写操作。已有 domain
ID 的轮换、验证、启用、暂停或路由更新只允许该 ID 的 GET 详情对账；注册未返回 ID 时不使用列表
猜测，也没有对账按钮。界面不会自动重复注册、轮换、验证、启用、暂停或路由更新。一次性 token 也不会
因对账而重新出现。该恢复模式同样约束 Agent 客户端：没有服务端精确幂等账本时，只能读取真实
状态后形成新的、明确的后续操作。

### 2.4 仍需要后端契约后才能实现的表达

下列界面在 API 未增加字段前不进入产品：

| 体验 | 需要的真实字段/接口 |
| --- | --- |
| 由 Agent 代表谁发送 | actor kind/id、`on_behalf_of`、委托有效期 |
| Agent 处理轨迹 | execution id、阶段、原因、时间、重试/接管状态 |
| 完整策略阻断与可执行下一步 | 实际 decision、拒绝原因、可执行动作及其授权边界 |
| 收件人级投递轨迹 | 受最小化保护的 delivery trace、协议/提供方证据和单独隐私评审 |

这些字段必须遵守租户、邮箱、RBAC、Scope 和 Active Human 边界；没有授权时统一隐藏，
不得以前端筛选替代服务端拒绝。

## 4. 键盘与无障碍

- 焦点顺序遵循：Rail → Queue controls → Queue rows → Detail actions/content → transient UI。
- 键盘选择和鼠标选择共享同一状态机；`aria-current`、选中样式和屏幕阅读器反馈一致。
- 所有图标按钮都必须有本地化可访问名称；图标文件不进入 i18n 字典。
- 所有对话框保持焦点圈闭，关闭后回到触发控件。
- 不超过 1007px 时邮件端的主操作、工具栏、返回和导航控件至少为 44×44px，且不依赖
  `pointer: coarse` 等设备特征；桌面端的紧凑密度保持不变，hover 不能是唯一提示方式。
- Agent Inspector 的 UUID 校验必须关联输入框与本地错误说明；刷新时控件继续保留在
  Tab 路径内，快照成功完成须以简短的 `aria-live` 文案通知，而不能用焦点跳转或 Toast
  打断管理员继续核对事实。
- Agent 发件证据的两个 UUID 输入都必须有可见标签、关联的本地校验说明和规范 UUID
  限制；默认收起的 `EvidenceInspector` 必须使用带 `aria-expanded` 的真实按钮，并在展开、
  收起或读取失败时保持输入及触发控件的焦点语义。
- 邮件域名的一次性 ownership token 仅在注册或 challenge 轮换成功后的当前 Dialog 可见；
  Dialog 关闭即清除内存，并把焦点返回触发器。DNS 验证、Activate、暂停和路由更新各自使用
  明确按钮与确认/说明，不把多步生命周期压缩为一个模糊的“保存”。未知写结果时写控件保持禁用；
  只有已有精确对象 ID 的只读刷新保留在键盘 Tab 路径并用简短 `aria-live` 文案说明已对账的快照。
