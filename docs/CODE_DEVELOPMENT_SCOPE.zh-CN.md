## 1. 产品责任

| 能力 | 负责方 | 当前边界 |
| --- | --- | --- |
| 验证码生成、存储、过期、校验、登录/注册 | 调用邮件服务的业务应用 | CopilotMail 不发行 Challenge、验证收据或登录凭证 |
| 应用发送包含验证码的邮件 | 业务应用调用批准的 SMTP Submission 服务 | 使用专用发信身份；不要求业务应用接入一套新的平台验证码 API |
| 第三方邮件客户端收发 | SMTP Submission + IMAP，TLS 加密 | 当前按外部邮件客户端及标准 SMTP 库解释，不更换现有邮件数据平面供应商 |
| Human / Agent / Admin API | 现有 Rust 控制面 | 保留已存在的邮件与管理契约；不因取消验证码功能删除 Agent API |
| 管理、审计、权限、可靠投递 | 邮件引擎与企业控制平面各自的强制边界 | 不把直连协议路径误称为自动继承了全部控制面策略/审计 |

验证码邮件可以由应用自己组织内容发送；邮件系统不需要知道、保存或验证其中的验证码。
本次不新增 ApplicationAdmin、验证码模板管理、猜码计数、验证码专属 worker 或验证结果服务。
若以后需要通用应用 REST 发信，应单独定义明确契约，而不是恢复托管验证码方案。
